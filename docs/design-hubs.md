## 🎯 المركز الأول: مركز إدارة الحجوزات (Booking Lifecycle Hub)

### الملفات المدمجة
| الواجهة الحالية | المصير |
|---|---|
| `QueryView.jsx` | ✅ يُحتفظ بها كمكوّن رئيسي للجدول والبحث |
| `CreateBookingView.jsx` | يُحوّل إلى Modal |
| `CancelView.jsx` | يُلغى — تُدمج وظائفه في QueryView |
| `PaymentView.jsx` | يُلغى — يُدمج في QueryView |

### هيكل الشاشة الجديد

```
┌─────────────────────────────────────────────┐
│  [🔍 بحث]  [➕ حجز جديد]  [📋 الكل/النشط/الملغي] │
├─────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────┐ │
│  │  جدول الحجوزات (نفس QueryView الحالي)    │ │

│  │  - فرز بعمود الحالة                     │ │
│  │  - كل صف: [💰دفعة] [🖨️عقد] [❌إلغاء]   │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘

          ↓  عند النقر على حجز  ↓

┌─────────────────────────────────────────────┐
│  🟢 بطاقة تفاصيل الحجز (Modal/Slideover)    │
│  ┌─────────────────────────────────────────┐ │
│  │  معلومات الحجز + حالة الدفع + المتبقي   │ │
│  │                                         │ │

### تدفق البيانات

```
الموظف ← ← ←
  [بحث/تصفية] → GET /api/bookings?search=&status=&date=
  [نقر حجز] → GET /api/bookings/:id
  [➕ حجز جديد] → POST /api/bookings
  [💰 دفعة] → PATCH /api/bookings/payment
  [❌ إلغاء] → POST /api/bookings/cancel
  [🖨️ طباعة] → printBooking(id)
  [✏️ تعديل] → PATCH /api/bookings/:id
```

### Modal تفاصيل الحجز — المكونات الداخلية

```
BookingDetailModal
├── Header: bookingId + customerName + status badge
├── Info Grid:
│   ├── التاريخ: startDate → endDate
│   ├── الباقة: packageName
│   ├── المبلغ: totalAmount
│   ├── المدفوع: paidAmount
│   ├── المتبقي: remainingAmount
│   └── الخزينة: cashAccountCode
│
├── Action Buttons:
│   ├── [✏️ تعديل] → فتح CreateBookingModal (edit mode)
│   ├── [💰 دفعة] → فتح PaymentForm inline
│   ├── [❌ إلغاء] → فتح CancelConfirmation
│   └── [🖨️ عقد] → طباعة العقد
│
└── Tabs:
    ├── Tab 1: تفاصيل الحجز (الأصناف، الباقات، الملاحظات)
    ├── Tab 2: سجل المدفوعات (جدول بالتواريخ والمبالغ)
    └── Tab 3: حركة الميدان (مرتبطة بـ FieldOps)
```

### Modal إنشاء/تعديل الحجز

```
CreateBookingModal
├── Step 1: العميل
│   ├── حقل الاسم (required)
│   ├── حقل الهاتف (required)
│   └── حقل العنوان (اختياري)
│
├── Step 2: التاريخ والنوع
│   ├── نوع الحجز: dropdown (أفراح/عزاء/مؤتمر/…)
│   ├── تاريخ البداية (DualCalendarPicker)
│   ├── تاريخ النهاية (DualCalendarPicker)
│   └── القاعة والصالة: Radios (صالة/فناء/كلاهما)
│
├── Step 3: الباقات والأصناف
│   ├── اختيار الباقة → حساب تلقائي للسعر
│   ├── إضافة أصناف إضافية مع الكميات
│   └── عرض إجمالي الأصناف
│
├── Step 4: المبلغ والدفعة
│   ├── إجمالي المبلغ (قابل للتعديل يدوياً)
│   ├── قيمة العربون
│   ├── حساب الخزينة المستلم
│   └── ملاحظات
│
└── Step 5: مراجعة وحفظ
    ├── عرض ملخص كامل
    ├── [🔙 رجوع] [💾 حفظ الحجز]
    └── بعد الحفظ → إغلاق Modal + تحديث الجدول
```

### الصلاحيات
- **الموظف**: بحث، عرض، طباعة، إنشاء حجز، تسجيل دفعة
- **لا يملك**: تعديل/حذف حجز موجود، إلغاء مع تسوية
- **المدير**: كل الصلاحيات + تعديل الحجوزات + إلغاء مع تسوية مالية

### Endpoints API المطلوبة

| الطريقة | المسار | الوظيفة | هل موجود؟ |
|---|---|---|---|
| GET | `/api/bookings` | قائمة الحجوزات مع تصفية | ✅ |
| POST | `/api/bookings` | إنشاء حجز جديد | ✅ |
| GET | `/api/bookings/:id` | تفاصيل حجز محدد | ❌ جديد |
| PATCH | `/api/bookings/:id` | تعديل حجز | ❌ جديد |
| PATCH | `/api/bookings/payment` | تسجيل دفعة | ✅ |
| POST | `/api/bookings/cancel` | إلغاء حجز | ✅ |

### الاعتمادات على Hubs أخرى
- **Booking→Field**: عند إنشاء الحجز، ينشئ سجل في حركة الميدان (اختياري)
- **Booking→Finance**: عند تسجيل دفعة، ينشئ قيد محاسبي في Finance_Ledger
- **Booking→Inventory**: عند تأكيد الحجز، يحجز الأصناف في المخزون

```

### صلاحية الحسابات حسب نوع القيد

```
مصروف عام:  حساب ← أي حساب من نوع expense (5000)
إيجار:     حساب ← 5005-01/02/03 فقط
رواتب:     حساب ← 5004 (تلقائي)
مسحوبات:   حساب ← 2203 (شجرة)
سند صرف:   حساب ← أي حساب صادر (asset/expense/liability)
سند قبض:   حساب ← أي حساب وارد (asset/income/liability)
تحويل:     حسابان ← من خزينة → إلى خزينة
```

### إعادة هيكلة شجرة الحسابات

الحالية: حساب واحد `5005` للإيجار مع فروع `5005-01` (صالة) و `5005-02` (مكتب).

المقترح: دعم لا نهائي للمستويات (حسب الحاجة):
```
5000 مصروفات
├── 5004 رواتب وعمالة
├── 5005 إيجار منشآت
│   ├── 5005-01 إيجار الصالة
│   ├── 5005-02 إيجار المكتب
│   └── 5005-03 إيجار المخزن
├── 5006 صيانة وتشغيل
│   ├── 5006-01 صيانة الخيام
│   └── 5006-02 صيانة الكراسي
└── 5007 مصروفات عامة
    ├── 5007-01 قرطاسية
    └── 5007-02 فواتير اتصالات
```

### ربط الميدان بالمخزون — التدفق التلقائي

```
1. الموظف يسجل تلف في صنف (مثلاً "خيمة 4*4 ممزقة")
   ↓
2. النظام ينشئ إدخال صيانة: status = "قيد الإصلاح"
   ↓
3. المخزون: fieldStatus = "damaged"، لا يظهر في المتاح
   ↓
4. بعد الإصلاح: الموظف يغيّر الحالة إلى "متاح"
   ↓
5. المخزون: fieldStatus = "available"، يعود للجدول
```

### الصلاحيات
- **مشرف الميدان**: جدول المهمات، تسجيل مصروفات، تسجيل تلف
- **أمين المخزن**: إضافة أصناف، جرد، صيانة
- **المدير**: كل الصلاحيات
